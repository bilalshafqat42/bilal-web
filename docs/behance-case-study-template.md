# Behance case study template

Written 2026-10-09. For the LEOS sales application first, then reusable for
Tomorrow World and any developer after.

**Do the images first.** This is a 15-minute job that can wait. Your own site is
where the enquiry happens; Behance ranks for Behance.

---

## Why the current description does not work

The LEOS project currently opens:

> "Designed and developed a custom sales presentation application for Leos
> Developments using the MERN stack. Tailored for the sales manager, the
> application enables dynamic presentations..."

It opens with the deliverable and the tech stack. That is a CV entry. It never
says what was broken, and it never says what changed.

Your own two best lines are not on the page at all:

> "it was like windows 98 before"
> "they not only use it on the sales screen but also on the tablets and mobile
> phones"

## The four blocks

| # | Block | What goes in it | Length |
| --- | --- | --- | --- |
| 1 | The problem | What was broken before you arrived | 2-3 lines |
| 2 | What I built | The screens, as bullets | 5 bullets |
| 3 | What changed | How they actually use it now | 2-3 lines |
| 4 | Credit | Stack, positioning, your link | 3 lines |

**Order matters.** Problem first, because nobody cares what you built until they
know what was wrong. Outcome third, because people using a tool beyond what it
was built for is the clearest proof it works. Stack last, because it matters to
one reader in twenty and putting it first makes you a developer rather than the
person who fixed a sales problem.

## The text, ready to paste

Swap anything in `[brackets]` per developer.

```
THE PROBLEM

[Developer] sales managers were presenting [AED multi-million] properties on a
tool that looked like Windows 98. Unit availability lived somewhere else.
Anything a customer asked for after the meeting had to be sent separately.

WHAT I BUILT

A sales presentation platform, built around what a sales manager actually does
in a room with a buyer:

• Exteriors, interiors and amenities for every development
• Live unit availability, pulled straight from the CRM
• 3D models that rotate and zoom
• A custom map showing the schools, hospitals and restaurants nearby
• Brochures and fact sheets, shareable from inside the app

WHAT CHANGED

It was built for the sales screen in the gallery. Sales managers started using
it on tablets and phones, and sending live offers and project details to
customers directly from it.

[Developments: Hadley Heights, Weybridge Gardens, Cavendish Square]

Built with React, Node and MongoDB. I handle the marketing these tools feed,
which is why the unit data and the campaigns speak to each other.

More work: bilalshafqat.com/portfolio
```

## Reusing it for other developers

| Block | Reuse? |
| --- | --- |
| 1. The problem | **Rewrite.** Each developer had a different starting point |
| 2. What I built | Reuse, minus any feature that one did not get |
| 3. What changed | **Rewrite.** What each team actually did with it |
| 4. Credit | Reuse exactly |

**Never paste blocks 1 and 3 identically across projects.** To a reader it is
filler. To Google it is duplicate content, and it will pick one page to show.

## Two things deliberately absent

**No invented numbers.** No conversion lift, no time saved, no percentage.
Bilal has not supplied any and a case study with invented figures is worth less
than one with none.

**No engagement type.** The text says what was built and what changed. It does
not say "freelance", "client" or "employee". That was his decision on
2026-10-09 and it is the honest position: describe the work and the role,
claim nothing about the contract.
