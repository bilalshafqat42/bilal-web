# bilalshafqat.com

## Live SEO data

`SEO-SNAPSHOT.md` in this folder holds real Search Console, Analytics and
AI-crawler figures for this site, exported from Performo. **Read it before
suggesting any SEO, content or metadata change** — it says what the site
actually ranks for, rather than what we might assume.

It is generated by a script and any edits here are overwritten.

**Regenerate it at the start of any SEO session**, not only when it looks
stale. On 2026-10-06 it was two days old and still described a site before
eleven new articles, six retargeted pages and a rewritten homepage. Two days is
long enough here. To refresh:

```
cd ~/Desktop/bilal/performo/performo/web
node scripts/export-seo-snapshot.mjs --company "Bilal Shafqat Digital"
```

Worth knowing when reading it:

- **Top-3 share** is the share of impressions in positions 1-3 — the zone
  answer engines quote from. Everything below that is invisible to them.
- **"Closest to page one"** lists queries at positions 4-15 with real
  demand behind them. Cheapest wins are there, not in the long tail.
- **Intent split** separates people learning from people ready to hire.
  A query with high impressions and commercial intent stuck at position
  40 is worth more attention than one at position 3 nobody searches for.
- **Answer fetches** are AI assistants opening a page because a person
  asked a question. Training crawls are not visibility and should be
  ignored when judging reach.

## Measuring the site itself

Four scripts in `scripts/`, all reading the **rendered** page rather than the
source, because four times in one week a title has claimed a keyword the body
did not contain and only reading the output caught it:

```
npm run daily     every tracked page scored, saved, diffed against yesterday
npm run audit     every sitemap URL: thin pages, titles, descriptions, breaks
npm run onpage    one page against one keyword, out of 100
npm run serp      what a result looks like in Google, by pixel width
```

Two rules they encode, both learned the hard way:

- **Count inside `<main>`.** The mega menu repeats fifteen service names on
  every page, so a whole-document count reports every keyword as covered
  everywhere (roadmap 341).
- **Match with optional stop words.** "mobile app development in Dubai"
  satisfies the keyword "mobile app development dubai". Literal matching marked
  a page down for being written in English (roadmap 358).
